# design-sync notes — @nightwatch/design-system

## Gotchas from this sync

- **Font files must be copied explicitly.** Tailwind CLI inlines the `@font-face` CSS text from `@fontsource/*` but does NOT copy the referenced `.woff2`/`.woff` asset files. `package.json`'s `build:fonts` script (`cp node_modules/@fontsource/*/files/*.woff* dist/files/`) handles this — if `npm run build` is ever split up or that script is dropped, the converter will re-flag `[FONT_DANGLING]`.
- **`DsQueryProvider` is a hand-added export**, not part of the original `frontend/` component — it's a thin `QueryClientProvider` wrapper needed because `CameraTile`, `SequenceEditor`, `ZonesEditor`, `DigestSettings`, and `ChatSidePanel` all call `useQuery`/`useMutation` directly with no provider of their own. Wired via `cfg.provider` + excluded from the component list via `componentSrcMap: {"DsQueryProvider": null}`.
- **`shims/lib/chatPanelState.ts` defaults `collapsed: false`** (the real app defaults to `true`/collapsed) — changed deliberately so `AppShell` and `ChatSidePanel` previews show the expanded panel rather than the collapsed rail button. This is a preview-only behavior change; it does not affect `frontend/` (this package is a snapshot, not imported by the app).
- **No automated render check or capture/grade ran this sync** — no local chromium/playwright, and the user chose to review `.review.html` manually in a browser instead of installing it (~200MB). All 16 previews compiled without error and were visually approved by the user via the served `.review.html`, but nothing here was machine-verified pixel-by-pixel. `_ds_sync.json`'s render hashes exist (from the build), but the upload was NOT gated on `package-validate.mjs`'s render check.
- **`WebRTCPlayer` has no meaningful static preview** — it opens a real `RTCPeerConnection` against the mocked `api.cameraWebRTCOffer` shim (which returns an empty answer SDP), so it renders as a blank video box. This is expected and was called out to the user before upload; not worth faking a WebRTC handshake to fix.
- **`HelpWidget` and `ChatSidePanel`'s "open" states can't be statically composed** — both gate their expanded UI behind internal `useState`/store state that isn't reachable from preview props. `HelpWidget` ships only its closed floating-button state. `ChatSidePanel` ships expanded (via the `chatPanelState` default above) but only its default "Events" tab — the "Ask" tab needs a click.
- **Overlay/full-page components** (`SequenceEditor`, `ZonesEditor`, `HelpWidget`, `ChatSidePanel`, `AppShell`, `Sidebar`, `WebRTCPlayer`) all use `fixed`/`h-screen` positioning — all have `cardMode: "single"` + explicit `viewport` overrides in `.design-sync/config.json` so they render inside their card instead of escaping it.
- **`componentSrcMap` src-match is 14/16, not 16/16** — two components (likely `Button`/`Toaster`, both in `components/ui/`) didn't fuzzy-match to a source path under the converter's default heuristics; grouping still worked correctly (`general/` group), and the `.d.ts` extraction was unaffected. Not investigated further since it didn't block anything — if it matters later, pin explicit paths via `componentSrcMap`.

## Re-sync risks

- If `frontend/`'s real components change, this package does NOT auto-update — it's a manually-copied **snapshot** (see `docs/superpowers/specs/2026-08-03-design-system-snapshot-package-design.md`). A re-sync of this repo will faithfully re-verify whatever is currently copied here, which may be stale relative to `frontend/`.
- The render check has never run against real chromium for this project. If a future sync installs playwright and runs the full check, expect it to be the FIRST real visual verification — treat any `[RENDER]`/`[RENDER_BLANK]` findings as new information, not a regression.
- Sample data lives in `src/shims/lib/samples.ts` and is duplicated (deliberately, per the recipe) into several `.design-sync/previews/*.tsx` files with slight variations (e.g. `SequenceEditor.tsx` and `ZonesEditor.tsx` use richer camera objects than the shim's default). If the underlying `Camera`/`Event`/`Digest` shape in `src/types/index.ts` changes, all of these need updating in parallel — nothing enforces they stay in sync.
- `dist/files/` (the copied font assets) is gitignored (under `dist/`) — a fresh clone must run `npm run build` (which includes `build:fonts`) before the converter, or `[FONT_DANGLING]` will resurface.
